## What runs

`build.py` copies every tracked `C/`, `CPP/`, and `Asm/` file to a fresh disposable
source directory and checks hashes. It rejects any engine source diff from the
reviewed base. It first builds an unchanged `Alone2` CLI, then changes only the
copy's `UI/Console/Main.cpp` to include `probe.inc` and call its opt-in test entry
point. Separate output directories prevent stale object reuse. It verifies all
other copied files remain byte-identical. Production checkout files are never
instrumented. Per-file hashes, executable hashes, exact command arrays, platform,
Python version, head, and GitHub run provenance are recorded in `build.json`.

The probe directly instantiates the real ZIP or TAR `CHandler`, opens a real
fixture via `CBufInStream`, and uses the real `SetProperties` overloads. One
handler object is retained across ten phases:

1. Fresh handler.
2. CP932.
3. CP936.
4. CP65001.
5. Empty unscoped helper call.
6. Empty scoped helper call.
7. CP936 again.
8. Properties for the other format only (filter leaves empty).
9. CP936 before direct reset (`cp936_direct` labels the precondition; it still
   uses the scoped helper, not a direct setter).
10. Direct `ISetProperties::SetProperties(NULL, NULL, 0)`.

Each phase captures properties immediately and after `Close`/`Open` on that same
object. It records numeric HRESULTs, VARTYPE, engine index, and every BSTR wchar
unit through `SysStringLen`, rather than parsing a displayed name. The stream's
backing vector outlives every open and is never resized. COM pointers release
before the vector. No borrowed pointers escape the probe. `wchar_bytes` records
the ABI width (2 on Windows, 4 on the tested Unix builds); the observed UString
non-BMP representation is still a surrogate pair, not a Unicode scalar.

`run.py` tests 23 deterministic, authored inputs; authored inputs are not
invented expected outputs. ZIP fixtures use stored payloads with explicit raw
names, EFS flags, CRCs and Unicode extras in local/central records. TAR fixtures
are bounded USTAR files with byte names and valid header/data checksums/layout.
The corpus covers:

- CP932, CP936 and UTF-8 for ZIP and TAR.
- Valid Unicode extra; wrong CRC; unsupported version; invalid UTF-8 extra.
- EFS versus conflicting valid extra; invalid UTF-8; encoded lone surrogate.
- Invalid bytes; reserved name; trailing dot/space; overlong component and long
  multi-component path; UNC-looking name syntax.
- Duplicate names, case pairs, composed/decomposed pairs and byte-escape/private
  use pairs, with distinct entry payload hashes to expose collision winners.

Each fixture gets eleven CLI property modes: default, scoped/unscoped
932/936/65001, other-format scope, both mixed-property orders, and invalid type.
Every ordinary probe-CLI listing is compared byte-for-byte with the unchanged
CLI listing. Extraction uses explicit `-aos -y` into a disposable empty directory;
no interactive overwrite choice or new collision policy is inferred.

Native filesystem probes use exclusive creation and capture actual enumeration
as Windows UTF-16 little-endian units or Unix bytes. Requested names are separate
from returned names and errors. Created ordinary files receive a fixed mtime
before a retained CLI ZIP create/list/extract round trip (`-mtc=off -mta=off`).
Raw console stdout/stderr bytes, command arguments, exit codes and output name /
content-hash trees are preserved. Sorting is only for filesystem inventories;
engine entries and CLI output remain in observed order.

### Native identity and collision observations

- All three platforms' native create/list/extract round trips returned exit 0;
  that is **not** a claim that every requested name survives unchanged.
- Linux retains `bytes-ff` / `bytes-fe` names as actual non-UTF-8 bytes through the
  round trip. The tested macOS volume rejects these raw byte creations (errno 92),
  and the archive extraction path instead records the retained Unicode escape
  representation. These results must not be homogenized.
- Native Windows accepted the lone-surrogate filename in the tested directory;
  the round-trip enumeration retained its `0xd800` code unit. Lossy display text
  cannot address that file faithfully. Python's attempted unrepresentable lone
  surrogate on Unix is recorded as such, not mislabeled as a native byte path.
- Windows and this macOS volume reject the second case-only exclusive creation;
  Linux accepts both. macOS also rejects the second normalization-equivalent
  exclusive creation, whereas Windows and Linux accept both spellings.
- Engine enumeration keeps both duplicate/case/normalization entries with their
  distinct indices even where `-aos` extraction produces one file. On Windows,
  the byte-escape pair also has identical displayed engine units under CP65001;
  index, not name, remains identity.
- Overlong component: listing succeeds, extraction returns 2 and an empty output
  tree on all three. Long multi-component path: listing/extraction return 0.
- Windows extraction maps `CON.txt` to `_CON.txt` and `end. ` to `end__`; the
  direct filesystem probe enumerates `end` for its `end. ` request. Unix captures
  those spellings without importing the Windows mapping.
- Case/normalization collision extraction records the first payload under
  explicit skip-existing policy where the volume aliases names. It is not a new
  recommendation to silently drop another entry.

### UNC boundary (explicit limit)

The corpus executes native handler/CLI **listing of UNC-looking archive names**
and records exact engine units for `\\b02-invalid-host\share\leaf.txt`.
It intentionally does not connect to a share or extract that fixture. This is
UNC **name-syntax identity**, not SMB authentication, share I/O, network stream
compatibility, `-spf` absolute extraction, or extended UNC path qualification.
Those operations must not be advertised as qualified from this report. No
network share, privileged service, or new security policy is configured here.

## Downstream constraints and remaining risks

Preserve the reviewed M2 contracts: `EngineText` owns u16 units, `NativePath` is
Windows-u16/Unix-bytes tagged data, display is lossy-only, and `EntryId` includes
session/generation/handler/index rather than a filename. Never truncate observed
wchar values into u16 blindly; the qualified fixtures demonstrate the current
contract but do not justify unchecked ABI conversions.

This bounded qualification is not universal filename/locale/filesystem coverage,
external-format interoperability certification, FFI safety approval, native GUI
reopen/rollback qualification, or desktop integration. The same handler's
close/open tested here is distinct from File Manager `CanReOpen`/rollback and
settings semantics, which remain B07/S9b work. No passwords, real user archives,
production extraction destinations, releases or shared branches were modified.
The Qt 6/QML → CXX-Qt → Rust → mature C/C++ direction remains unchanged.
