## Threat boundary and candidate implementations

The trusted parent creates separate baseline and sandbox envelopes. Every target
is a new disposable control file. The unconfined baseline deliberately modifies
only its own controls and proves those operations actually work; it is not a
fallback after sandbox failure. The sandbox probe tries the same bounded writes.
No existing user file is read or written as a control. All probes have empty or
minimal environments, closed inherited descriptors, and null stdin. The Windows
AppContainer child inherits no handles and an explicitly empty environment.

- Linux: bubblewrap unshares namespaces, drops all capabilities, starts a new
  session, binds system runtime and the probe read-only, and places output in
  fresh tmpfs. **No host directory is writable-mounted.** The outside controls
  have a separate read-only mount. This deliberately avoids the well-known
  preexisting-hardlink hole of binding a host output directory writable: a
  read-only alias elsewhere does not protect an inode reached through a writable
  bind. A fresh tmpfs cannot contain incoming external inode aliases. No `/proc`,
  host home, credentials, host `/tmp`, or device tree is mounted. The probe's raw
  stdout is captured by the parent; there is no host-backed output tree.
- macOS: native `sandbox-exec`, deny by default; read access to the explicit
  system runtime and disposable envelope, writes only to the resolved work path.
  No broad `mach-lookup`, network, or process-fork allowance. This is an empirical
  candidate, not an assertion that path rules correctly contain hardlink/reparse
  races. The exact `.sb` is retained. Deprecation/OS differences may reject it.
- Windows: native AppContainer via `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`,
  a derived SID without creating a profile, zero capabilities, no fallback.
  Only the disposable envelope gets SID read/execute rights; its work directory
  gets write rights and a low-integrity label. No global ACL, privilege, developer
  mode, security policy, or AppContainer profile is changed. A static CRT probe
  avoids granting access to a user-installed Python runtime. Win32 errors and
  build output are retained. The fixed test SID is not a claim of inter-run
  adversarial isolation; concurrent untrusted processes are not authorized.

These are bounded file-write candidates, **not** general malicious-program
sandboxes. Network denial, IPC, registry, resource limits, descendant cleanup,
preexisting aliases, reparse variants and active races require further native
controls and review before any hostile archive. The fixed native probe spawns
no descendants. Windows launcher timeout termination is failure, never graceful
cancellation evidence.

## Current control relations (not invented legacy goldens)

`controls_pass` requires all expected keys, both exit codes zero, all baseline
operations successful, and all sandbox outside writes denied with sentinel bytes
unchanged. Missing/malformed output, compiler/launcher failure, unsupported native
platform or any inside operation failure means not qualified.

Inside controls: file creation, rename, hardlink creation/write, symlink
creation/write, and refusal to write a read-only file. These must also succeed
in the unconfined control (including the intentional refusal). This detects
coarse isolation that destroys the link or simple permission behavior of interest.

Outside controls: absolute-path write, `../outside` traversal, an absolute
symlink followed by write, and creating then writing a hardlink alias to an
outside sentinel. The raw post-expression errno/Win32 last error is diagnostic;
it is not meaningful on a successful expression and does not distinguish all
short-circuited substeps. No error is relabelled as an archive HRESULT.

Limitations: Linux uses tmpfs rather than a host archive target volume; EXDEV
for external hardlink creation is a mount-boundary control, not retained-engine
hardlink policy. Passing inside checks establishes only these elementary native
operations, not general ACL parity. It cannot qualify Windows reparse semantics,
full metadata fidelity, network shares, or cross-volume engine outcomes.

The unit tests include missing-evidence rejection and temporary in-memory
mutations of the acceptance relations; those dictionaries test validator logic,
not archive golden data. A native end-to-end test confirms that both success and
safe rejection retain a report with archive authorization false. That test may
pass on a rejected candidate; the separate capture invocation must return zero
for the CI candidate job to pass.

## Evidence and remaining qualification

Local initial Linux execution: `cc -std=c11 -Wall -Wextra -Werror` build and
three unittest tests passed. Baseline operations all returned true; sandbox
inside controls all returned true; outside writes all returned false. Raw Linux
outside diagnostics were EROFS (30) for direct/traversal/symlink paths and EXDEV
(18) for hardlink creation. All sandbox sentinels remained byte-identical.
These observations were collected in `work/local-1/`, not manufactured expected
archive data. Subsequent native run IDs and immutable evidence are recorded on
the card and below when available.
