## Method and bounded effects

`build.py` copies tracked engine and assembly sources to a fresh directory,
asserts no engine difference from reviewed `d9c3b65`, and builds unchanged Alone2.
The second build uses separate objects and changes only the disposable copies of
`UI/Console/Main.cpp` and `Common/FileStreams.cpp`, with two included test files.
All other source hashes are checked after the build.

`probe.inc` directly opens real archive files using `CInFileStream`, then real
7z/ZIP/TAR handlers. It records open/count/property/close HRESULTs, engine indices,
VARTYPE, all three reserved precision words, FILETIME low/high words, numeric
attributes/size, bools, and BSTR wchar units. COM owners release before the input
stream owner; no borrowed property pointers escape. `wchar_bytes` is explicit.
Raw time type/precision must not be reduced to formatted timestamps in M2.

`fault.inc` is an opt-in test-only seam at `CInFileStream::Read` and
`COutFileStream::Write`. It caps requested chunks at seven bytes; error modes
allow 4096 requested bytes before returning the platform-mapped read-fault or
disk-full HRESULT. All permitted operations still use real retained native I/O.
The counter measures **permitted**, not necessarily OS-completed, bytes. It is
process-local and designed for these single-input/output `-mmt=off` commands, not
concurrent fault injection. Raw stderr proves activation and error triggering.
Normal probe-CLI listings match unchanged CLI listings byte-for-byte. This
checks the no-fault path; it is not a claim that injected failures are naturally
occurring kernel events or that every native wrapper is independently qualified.

`run.py` uses new worktree-local sandboxes and never reads user archives. Inputs
are authored deterministic payloads, not authored expected outputs. A 16 MiB
sparse fixture characterizes output allocation. The >4 GiB input has only two
written extents; Windows must successfully set `FSCTL_SET_SPARSE` before seeking.
Unix source allocation is bounded to less than 1 MiB. The large compressed
archive must be below 64 MiB; decompression streams through an 8 MiB hash buffer
rather than allocating a 4 GiB destination. Each regular CLI command has a
timeout, and the proposed native job has a 35-minute overall bound. A hung
streaming decompressor still relies on that enclosing job/process timeout.
Sandboxes are retained for diagnosis, not recursively deleted by this harness.

## Measured Linux results

- Six metadata round trips: 7z/ZIP/TAR, each with `TZ=UTC0` and `TZ=EST5EDT`.
  Creation, listing and extraction all return 0; all payload hashes survive.
- Input mtime `1700000001123456789` becomes `1700000001123456700` for 7z/ZIP and
  `1700000001000000000` for default TAR. This observation includes the directory
  mtime after child extraction. The two tested timezone settings give the same
  extracted mtimes; this does not characterize every historical/DST timestamp.
- Executable mode `0755`, readonly `0444`, directory `0750`, and ordinary file
  modes survive on this Linux volume. Windows readonly semantics are not inferred.
- `user.b03` xattr and a named POSIX ACL are successfully applied to the input.
  Default extracted ordinary files have empty xattr inventories; neither the
  user xattr nor `system.posix_acl_access` is preserved. This is an observation,
  not an approved new portable ACL mapping.
- Separate `-sni`, `-sns`, and combined `-sni -sns` 7z creation probes each return
  exit 2 with `E_NOTIMPL : Not implemented`. Invalid ZIP method property returns
  exit 2 with `E_INVALIDARG : One or more arguments are invalid`. The times-on
  7z probe succeeds and records raw time properties. CLI labels are not numeric
  handler HRESULTs; only the direct property probe records those numerically.
- Twelve fresh-create/update runs cover no fault, short read, short write,
  read error, disk-full injection, and missing input. Short I/O runs succeed and
  produce the exact same archive SHA-256 as their no-fault control.
- Fresh-create read/write failure returns 2 and leaves no archive. Missing input
  returns warning exit 1 and leaves a 22-byte empty ZIP. Do not flatten warning
  into either complete success or no effects.
- Update read/write failure returns 2 and retains the byte-identical 165-byte
  original archive; missing input returns 1 and likewise retains it. These early
  failures do **not** prove rollback/atomicity for later rename/cross-volume
  replacement failures.
- Real Linux `/dev/full` receives an unchanged-CLI extraction stdout stream,
  returning exit 2 with `errno=28 : No space left on device`. The host disk is
  never filled. This is `CStdOutFileStream` kernel evidence, distinct from
  `COutFileStream` injected archive-output failures.
- The 16 MiB sparse source has `st_blocks=16`; default retained extraction has
  `st_blocks=32768`, with identical content SHA-256. Sparse logical contents
  survive, but this operation does not preserve sparse allocation.
- Actual ZIP64 source/extracted size is `4294967329`. Central directory reports
  extract version 45 and ZIP64 extra ID `0x0001`. Archive size is 5040025 bytes.
  The entire extracted stream matches source SHA-256
  `6dcc95374a10eaf4726e149603bc3727d89004f440c9a0879580f9132044ff2d`.
- Direct retained native seeks cover negative absolute offset, offset
  `4294967313`, EOF, beyond EOF, and invalid origin. Error-position output is
  labeled undefined, never used to infer a portable position guarantee.
